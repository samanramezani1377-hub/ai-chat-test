# نقشه صفحه‌های رابط کاربری

**وضعیت:** 🔒 یکپارچه‌سازی‌شده برای UI v1

> 🔴 **تمام صفحه‌ها و متن‌های قابل مشاهده باید فارسی و راست‌چین (RTL) باشند.**

## ۱. درخت کلی

```text
رابط کاربری
├── گفت‌وگو
│   ├── گفت‌وگوی فعال
│   └── پیام‌ها و Composer
├── فضای کار
│   ├── Timeline مرکزی
│   ├── خلاصه اجرای جاری
│   └── جزئیات لایه‌ای هر Event با Expand
├── عیب‌یابی
│   ├── خطاها
│   └── گزارش فنی و Trace کامل
├── تنظیمات
│   ├── هوش مصنوعی / مدل
│   ├── گفتگو
│   ├── ظاهر
│   └── حریم خصوصی
└── درباره برنامه
```

## ۲. Header مشترک

تمام سطوح اصلی از Header مشترک استفاده می‌کنند:

```text
[ گفت‌وگو │ کار │ ⋯ ]    ● آماده
                          مدل محلی       [ ☰ ]
```

`⋯` منوی سریع «لاگ / تنظیمات» را باز می‌کند و `☰` Sidebar ساختاری را باز می‌کند.

## ۳. گفت‌وگو

گفت‌وگو سطح اصلی برنامه است.

### پیام کاربر

حباب نیمه‌شفاف با رنگ روشن و آرام، با جهت بصری آبی روشن.

### پاسخ مدل

بدون حباب و Surface سنگین؛ Typography و فاصله‌گذاری محور اصلی هستند.

### Composer

Floating و Responsive است و در موبایل، تبلت و دسکتاپ ابعاد متناسب دارد. سقف ارتفاع دارد و پس از آن متن داخلی Scroll می‌شود.

### ارسال

دکمه ارسال تطبیقی و گرد است. روی دسکتاپ `Enter` خط جدید و `Shift + Enter` ارسال است. روی موبایل Enter فقط خط جدید ایجاد می‌کند و ارسال فقط با دکمه انجام می‌شود.

## ۴. Sidebar

Sidebar از سمت راست باز می‌شود و روی محتوای اصلی Overlay نیمه‌شفاف دارد.

ساختار:

```text
گفت‌وگوی جدید

ابزار
├── فضای کار
├── عیب‌یابی
└── تنظیمات

اطلاعات
└── درباره برنامه

اخیر
├── گفت‌وگوی فعلی
├── ۵ گفت‌وگوی اخیر
└── مشاهده بیشتر → +۵ مورد
```

## ۵. صفحات تخصصی

### فضای کار

Workspace یک فضای کار Timeline محور است و **Timeline مرکزی، مرکزیت بصری صفحه** را دارد. اطراف Timeline فقط خلاصه اجرای جاری و اطلاعات کمکی کم‌حجم قرار می‌گیرند؛ پنل جزئیات مستقل و ثابت وجود ندارد.

هر Event/Action در حالت عادی مینیمال است و شامل اطلاعات اصلی مانند نام، وضعیت و نتیجه/عنوان خطا می‌شود. Metricهای پردازشی واقعی مانند زمان اجرا، حجم داده، تعداد توکن یا مرحله اجرا در صورت وجود، کوچک‌تر و کم‌رنگ‌تر نمایش داده می‌شوند.

جزئیات با **Expand از پایین همان Event** باز می‌شوند و می‌توانند چند لایه داشته باشند:

```text
Action
├── خلاصه وضعیت
├── ▼ جزئیات
│   ├── ▼ اطلاعات درخواست
│   ├── ▼ پردازش و Trace مربوط به Event
│   ├── ▼ Preview / Result
│   └── مشاهده جزئیات → عیب‌یابی همان Execution
└── کنترل‌های مجاز همان لحظه
```

کنترل‌ها Context-aware هستند؛ فقط عملیات واقعی و مجاز همان Action/وضعیت نمایش داده می‌شوند. تأیید و رد در صورت نیاز از Workspace قابل انجام است.

اجرای جاری در همان Timeline مشخص و به‌صورت ظریف برجسته می‌شود. خلاصه اجرای جاری می‌تواند وضعیت، مرحله فعلی و زمان سپری‌شده را نشان دهد. **Progress Bar درصدی وجود ندارد.**

Action Trace در Timeline ادغام می‌شود و Timeline جداگانه‌ای برای Trace ساخته نمی‌شود. گزارش فنی کامل Trace و Errorها در عیب‌یابی قابل دسترسی است.

### عیب‌یابی

برای مشاهده خطاها، وضعیت‌های فنی و گزارش کامل Execution استفاده می‌شود. داخل آن مسیر مستقل **«خطاها»** وجود دارد.

«مشاهده جزئیات» از Workspace باید Context همان Action/Execution را حفظ کند و کاربر را مستقیم به گزارش متناظر در عیب‌یابی ببرد.

اطلاعات فنی می‌تواند LTR باشد، ولی متن پیرامون آن فارسی و RTL است.

### تنظیمات

تنظیمات واقعی برنامه در این بخش مدیریت می‌شوند. تنظیمات UI نباید شامل گزینه تغییر اندازه Header از C به B باشد؛ آن قابلیت در صورت نیاز یک تصمیم پیاده‌سازی داخلی است.

### درباره برنامه

اطلاعات نسخه و مشخصات برنامه در این بخش قرار می‌گیرند.

## ۶. قواعد عمومی

- هیچ صفحه‌ای نباید برای دورزدن Navigation اصلی، Header مستقل و متناقض بسازد.
- وضعیت‌های مرتبط هر صفحه باید با قرارداد `STATES.md` سازگار باشند.
- UI نباید به داده جعلی، Mock یا Placeholder برای نمایش وضعیت واقعی متکی باشد.
- اطلاعات پردازشی فقط وقتی نمایش داده شوند که Core/Execution واقعاً آن‌ها را ارائه کند.
- Performance، Accessibility و RTL در تمام صفحات الزامی هستند.
- جزئیات Contextual هر Event داخل Expand همان Event قرار دارد و پنل Contextual مستقل در Workspace وجود ندارد.
- Progress Bar درصدی در نمایش اجرای جاری Workspace وجود ندارد.
