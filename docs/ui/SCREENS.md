# نقشه صفحه‌های رابط کاربری

**وضعیت:** 🔒 یکپارچه‌سازی‌شده برای UI v1

> 🔴 **تمام صفحه‌ها و متن‌های قابل مشاهده باید فارسی و راست‌چین (RTL) باشند.**

## مرجع ساختاری

درخت کامل UI در [`UI_TREE.md`](UI_TREE.md) مرجع Canonical است. این سند فقط جزئیات Screenها را تکمیل می‌کند.

## ۱. درخت صفحه‌ها

```text
رابط کاربری
├── App Shell
│   ├── Header مشترک
│   └── Sidebar
├── گفت‌وگو
│   ├── گفت‌وگوی فعال
│   ├── پیام‌های کاربر
│   ├── پاسخ مدل
│   └── Composer
├── فضای کار
│   ├── خلاصه اجرای جاری
│   ├── Timeline مرکزی
│   ├── Event / Action
│   │   └── Expand لایه‌ای
│   └── تاریخچه عملکرد
├── عیب‌یابی
│   ├── خطاها
│   ├── گزارش Execution / Trace
│   ├── عملکرد
│   └── گزارش کار حساس
├── تنظیمات
│   ├── مدل
│   ├── استنتاج
│   ├── زمینه
│   ├── عامل
│   ├── فضای کار
│   ├── لاگ و عیب‌یابی
│   ├── عملکرد
│   └── امنیت و تأیید
└── درباره برنامه
```

## ۲. Header مشترک

```text
[ گفت‌وگو │ کار │ ⋯ ]    ● آماده
                          مدل محلی       [ ☰ ]
```

`⋯` منوی سریع «لاگ / تنظیمات» را باز می‌کند و `☰` Sidebar ساختاری را باز می‌کند.

## ۳. گفت‌وگو

گفت‌وگو سطح اصلی برنامه است.

### پیام کاربر

حباب نیمه‌شفاف با رنگ روشن و آرام، با جهت بصری آبی روشن.

### پاسخ مدل

بدون حباب و Surface سنگین؛ Typography و فاصله‌گذاری محور اصلی هستند.

### Composer و ارسال

Composer Floating و Responsive است و سقف ارتفاع دارد؛ پس از سقف، متن داخلی Scroll می‌شود.

- دسکتاپ: `Enter` خط جدید، `Shift + Enter` ارسال.
- موبایل: `Enter` خط جدید و ارسال فقط با دکمه.
- هنگام تولید، دکمه ارسال طبق Q21 به «توقف» تبدیل می‌شود.

## ۴. Sidebar

Sidebar از سمت راست باز می‌شود و Overlay نیمه‌شفاف روی محتوای اصلی دارد. جزئیات رفتاری در `NAVIGATION.md` است.

## ۵. فضای کار

Workspace یک فضای کار **Timeline محور** است و Timeline مرکز بصری آن است.

اطلاعات اطراف Timeline محدود به خلاصه اجرای جاری و اطلاعات کمکی کم‌حجم هستند. پنل Contextual مستقل و ثابت وجود ندارد.

### Event / Action

هر Event در حالت عادی مینیمال است:

```text
● ایجاد فایل
  ✓ انجام شد
  ایجاد فایل · 1.2s · 14 KB
```

Metricهای پردازشی واقعی مانند زمان، حجم داده، تعداد توکن یا مرحله، فقط در صورت ارائه واقعی توسط Core، کوچک‌تر و کم‌رنگ‌تر نمایش داده می‌شوند.

### Expand لایه‌ای

```text
Action
├── خلاصه وضعیت
├── ▼ جزئیات
│   ├── ▼ اطلاعات درخواست
│   ├── ▼ پردازش و Trace همان Event
│   ├── ▼ Preview / Result
│   ├── ▼ Verification / Evidence در صورت وجود
│   ├── ▼ Recovery در صورت وجود
│   └── مشاهده جزئیات → عیب‌یابی همان Execution
└── کنترل‌های مجاز همان لحظه
```

کنترل‌ها Context-aware هستند؛ فقط عملیات واقعی و مجاز همان Action/وضعیت نمایش داده می‌شوند. تأیید و رد درخواست‌های قابل تأیید از Workspace انجام می‌شوند.

### اجرای جاری

اجرای جاری در همان Timeline به‌صورت زنده مشخص و ظریف برجسته می‌شود. خلاصه آن می‌تواند وضعیت، مرحله فعلی و زمان سپری‌شده را نشان دهد.

**Progress Bar درصدی وجود ندارد.**

### Trace و Result

Action Trace داخل Timeline ادغام می‌شود و Timeline جداگانه‌ای برای Trace وجود ندارد. گزارش فنی کامل Trace و Errorها در عیب‌یابی قابل دسترسی است.

Preview/Result داخل Expand همان Event قرار می‌گیرد. خروجی‌های بزرگ در حالت عادی Timeline را اشغال نمی‌کنند.

### تاریخچه عملکرد

تاریخچه عملکرد نیز در Workspace قرار دارد و هر اجرا جزئیات Expand‌شونده، فیلتر، مقایسه و خروجی گزارش دارد. سوابق عملکردی در عیب‌یابی نیز قابل بررسی هستند.

## ۶. عیب‌یابی

برای مشاهده خطاها، وضعیت‌های فنی و گزارش کامل Execution استفاده می‌شود و مسیر مستقل **«خطاها»** دارد.

```text
عیب‌یابی
├── خطاها
├── گزارش Execution
│   ├── Trace
│   ├── Error
│   ├── Verification
│   └── Recovery
├── عملکرد
└── گزارش کار حساس
```

«مشاهده جزئیات» از Workspace باید Context همان Action/Execution را حفظ کند و مستقیم روی گزارش متناظر در عیب‌یابی باز شود.

کارت‌های کار حساس از تأییدهای معمولی از نظر بصری متمایز هستند و گزارش فارسی قابل مشاهده دارند.

## ۷. تنظیمات

تنظیمات با Central Settings Core مدیریت می‌شوند. کنترل‌های واقعی Inference طبق Q26 در تنظیمات قرار می‌گیرند. Performance طبق Q40 دارای Visibility مستقل برای دسته و Metric است.

## ۸. درباره برنامه

اطلاعات نسخه و مشخصات برنامه در این بخش قرار می‌گیرند.

## ۹. قواعد عمومی

- هیچ صفحه‌ای نباید Navigation اصلی را دور بزند.
- وضعیت‌های هر صفحه باید با `STATES.md` سازگار باشند.
- UI نباید به Mock یا Placeholder برای وضعیت واقعی متکی باشد.
- اطلاعات پردازشی فقط از داده واقعی Core/Execution می‌آیند.
- جزئیات Contextual داخل Expand همان Event هستند.
- Progress Bar درصدی در Workspace وجود ندارد.
- تغییر ساختار صفحه‌ها ابتدا باید در `UI_TREE.md` ثبت شود.
