## گفت‌وگو

Chat صفحه آغازین برنامه است. پیام‌های کاربر و دستیار، پاسخ Streaming، وضعیت Agent، تأیید Action و Composer در همین مقصد قرار دارند. متن‌های جدید باید خودکار در دید باقی بمانند. پاسخ دستیار از Typography و فاصله‌گذاری استفاده می‌کند و پیام کاربر حباب سبک دارد.

## تاریخچه گفتگوها

تاریخچه مقصد مستقل است و از ConversationHistoryRepository تغذیه می‌شود. جستجو در نسخه فعلی روی مجموعه بارگذاری‌شده انجام می‌شود. بازکردن گفتگو همان شناسه و پیام‌های ذخیره‌شده را در Chat فعال می‌کند. پیش‌نمایش آخرین پیام برای تشخیص گفتگوها نمایش داده می‌شود.

## تنظیمات

Settings تنها مرکز مدیریت پیکربندی است. مدل محلی، ورود فایل GGUF، فعال‌سازی/خارج‌کردن مدل، Provider، تنظیمات پاسخ، Context، Agent و تنظیمات کامل Voice باید از این مقصد در دسترس باشند. تنظیمات صوتی نباید فقط در صفحه مکالمه صوتی پنهان باشند.

## مکالمه صوتی

صفحه Voice برای مکالمه زنده است، نه مدیریت مدل‌ها. Transcript باید در همان لحظه دریافت گفتار و Tokenها به‌روزرسانی شود و خودکار به انتهای فهرست برود. پیام‌های صوتی از همان Conversation Repository استفاده می‌کنند و در تاریخچه عمومی قابل بازکردن هستند.

## Workspace و Diagnostics

Workspace برای Timeline عملیات، Preview، Approval و Verification است. Diagnostics برای Error، Trace، Performance و گزارش فنی است. این صفحات تخصصی حفظ می‌شوند.

## قواعد

- مقصد آغازین Chat است، به‌جز Deep Link/Wake Word معتبر.
- UI نباید Core یا Runtime را دوباره پیاده‌سازی کند.
- قابلیت ساختگی، وضعیت Mock یا ادعای GPU فعال بدون داده واقعی ممنوع است.
- UI فارسی و RTL است.
- هر قابلیت جدید باید به Contract واقعی Core متصل شود.
