# سیستم طراحی رابط کاربری

**وضعیت:** 🔒 مشخصات UI v1 در حال یکپارچه‌سازی نهایی
**دامنه:** قرارداد بصری مشترک تمام UI

> 🔴 **الزام قطعی: کل رابط کاربری برنامه باید فارسی و راست‌چین (RTL) باشد.** این الزام برای Header، Sidebar، Chat، Work، Settings، Diagnostics، About، Menu، Dialog، Status، Error، Empty State و تمام متن‌های قابل مشاهده اعمال می‌شود. داده‌های ذاتاً فنی مانند نام مدل، کد، URL و شناسه فنی می‌توانند LTR باشند، اما ساختار پیرامون آن‌ها فارسی و RTL باقی می‌ماند.

## ۱. هویت بصری

زبان بصری پروژه **Clean Conversational Premium** است:

- مدرن
- تمیز
- آرام
- حرفه‌ای
- سبک و کم‌حجم
- متمرکز بر تجربه گفتگو
- کمینه‌گرایی بصری
- عمق بصری ظریف

UI نباید به Glassmorphism افراطی، Neon، Cyberpunk، Cardهای سنگین یا Shadowهای شدید تبدیل شود.

## ۲. Surface و عمق

- Surfaceها نرم و مستقل هستند.
- Shadowها ظریف و کنترل‌شده‌اند.
- Blur سنگین یا دائمی ممنوع است.
- شفافیت فقط در حد سبک و در صورت ارزش UX مجاز است.
- Surface Premium نباید باعث افت محسوس Performance شود.
- Radiusها باید از یک خانواده مشترک Design System استفاده کنند.

## ۳. Header

Header یک Surface نرم و کمی برجسته است و سه ناحیه دارد:

```text
[ گفت‌وگو │ کار │ ⋯ ]    ● آماده
                          مدل محلی       [ ☰ ]
```

- گروه «گفت‌وگو / کار / ⋯» کمتر از نصف عرض Header را اشغال می‌کند.
- گزینه فعال با خط ظریف زیر همان گزینه مشخص می‌شود.
- Runtime/AI بین دو ناحیه قرار می‌گیرد و دوخطی است.
- ارتفاع Runtime با ارتفاع دکمه‌های Header برابر و هم‌تراز است.
- دکمه Sidebar در سمت راست گرد و مستقل است.
- Header کنترل دائمی دیگری ندارد.

## ۴. Sidebar

Sidebar از سمت راست باز می‌شود و Surface Premium تطبیقی دارد:

- موبایل: نزدیک‌تر به لبه و کم‌فاصله.
- تبلت: کمی شناورتر.
- صفحه بزرگ: شناورتر و باریک‌تر.

هنگام بازبودن، Overlay نیمه‌شفاف روی محتوای اصلی قرار می‌گیرد.

ساختار محتوا:

```text
گفت‌وگوی جدید

ابزار
├── فضای کار
├── عیب‌یابی
└── تنظیمات

اطلاعات
└── درباره برنامه

اخیر
├── گفت‌وگوی فعلی
├── گفت‌وگوی ۱
├── گفت‌وگوی ۲
├── گفت‌وگوی ۳
├── گفت‌وگوی ۴
├── گفت‌وگوی ۵
└── مشاهده بیشتر
```

## ۵. گفتگوهای اخیر

هر آیتم شامل عنوان، Indicator وضعیت و زمان است.

- عنوان عنصر اصلی و خواناتر است.
- زمان در سمت چپ قرار می‌گیرد.
- زمان کوچک، مینیمال و خاکستری/طوسی کم‌رنگ است.
- گفت‌وگوی فعلی با Highlight ظریف + Indicator مشخص می‌شود.
- تاریخچه مستقیماً در Sidebar نمایش داده می‌شود.
- «مشاهده بیشتر» هر بار پنج مورد دیگر اضافه می‌کند.

تعامل:

- کلیک/لمس → بازکردن.
- Long Press → منوی بازشونده از همان نقطه.
- منو: باز کردن / تغییر نام / حذف.
- حذف قرمز است.
- حذف فوری است و Undo به مدت ۱۰ ثانیه نمایش داده می‌شود.
- Undo شامل شمارشگر معکوس کوچک و `×` برای بستن پیام است.

## ۶. پیام‌ها

پیام کاربر و پاسخ مدل سطوح متفاوتی دارند:

- پیام کاربر → حباب مستقل، نیمه‌شفاف و با رنگ روشن و آرام؛ آبی روشن به‌عنوان جهت بصری مصوب.
- پاسخ مدل → بدون حباب و Surface سنگین؛ Typography و فاصله‌گذاری نقش اصلی را دارند.

## ۷. Composer

Composer پایین صفحه به‌صورت **Floating و Responsive** است:

- موبایل: شناور و جمع‌وجور.
- تبلت: کمی بزرگ‌تر.
- دسکتاپ: عرض محدود و مرکزگرا.
- با افزایش متن رشد می‌کند تا سقف ارتفاع مشخص.
- بعد از سقف، متن داخلی Scroll می‌شود.

دکمه ارسال تطبیقی است:

- موبایل: گرد و کوچک.
- تبلت: کمی بزرگ‌تر.
- دسکتاپ: گرد و متوسط.
- متن خالی: غیرفعال.
- متن وجود دارد: فعال.
- هنگام ارسال: Loading.

## ۸. ورود متن و کلیدها

### دسکتاپ

- `Enter` → خط جدید.
- `Shift + Enter` → ارسال.

### موبایل

- `Enter` → خط جدید.
- ارسال فقط با دکمه ارسال.
- Enter هرگز پیام را ارسال نمی‌کند.

## ۹. Runtime / AI Status

وضعیت محلی با نقطه رنگی و متن نمایش داده می‌شود:

- **آماده** → ثابت.
- **در حال کار** → Pulse ظریف.
- **در حال تولید** → Pulse/تنفس ظریف.
- **خارج از دسترس** → ثابت.
- **خطا** → ثابت.

هر وضعیت رنگ مخصوص خود را دارد، اما رنگ تنها نشانه نیست؛ متن و semantics نیز وضعیت را منتقل می‌کنند.

## ۱۰. تایپوگرافی

اولویت با خوانایی فارسی است.

- عنوان‌ها سلسله‌مراتب مشخص دارند.
- متن اصلی واضح و خوانا است.
- Metadata مانند زمان کوچک‌تر و کم‌رنگ‌تر است.
- متن فنی در صورت نیاز Monospace است.
- Font Scaling سیستم باید حفظ شود.

## ۱۱. رنگ

رنگ‌ها باید Token محور باشند و شامل نقش‌های عمومی، Surface پیام کاربر، وضعیت Runtime، خطا، هشدار، موفقیت، Focus و جداکننده باشند.

رنگ وضعیت یا فرستنده نباید تنها روش انتقال معنا باشد.

## ۱۲. Motion

Motion باید کوتاه، نرم و هدفمند باشد:

- باز/بسته‌شدن Sidebar و Menu.
- Pulse وضعیت‌های فعال Runtime.
- Loading ارسال.
- نمایش و حذف Undo.

انیمیشن تزئینی دائمی، شدید یا کند ممنوع است. Reduced Motion باید رعایت شود.

## ۱۳. Accessibility

- کنتراست مناسب.
- ناحیه لمس مناسب.
- Semantic Label برای کنترل‌ها.
- مدیریت Focus.
- پشتیبانی از بزرگ‌شدن متن.
- وضعیت قابل فهم بدون وابستگی به رنگ.
- Keyboard/IME مناسب Platform.
- Long Press تنها مسیر دسترسی به عملیات نباشد.

## ۱۴. Performance

ظاهر Premium نباید هزینه غیرضروری به Performance تحمیل کند.

- Blur سنگین ممنوع.
- Shadowهای زیاد ممنوع.
- Motion محدود.
- Surfaceها تا حد امکان سبک.
- هیچ افکت بصری نباید جای کیفیت و پایداری Core را بگیرد.

## ۱۵. آمادگی پیاده‌سازی

تمام اندازه‌ها، فاصله‌ها، Radiusها، رنگ‌ها، Breakpointها و Motionها باید از Token/Contractهای مرکزی پیروی کنند. هدف این است که تغییرات کنترل‌شده آینده، مانند کوچک‌کردن Header از اندازه C به B، با تغییر محدود در Token انجام شوند و به بازطراحی معماری نیاز نداشته باشند.
