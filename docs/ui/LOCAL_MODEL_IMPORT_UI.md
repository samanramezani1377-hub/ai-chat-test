# راهنمای UI/UX — Import Model محلی

**وضعیت:** 🔒 قرارداد UI v1
**مرجع ساختاری:** [`UI_TREE.md`](UI_TREE.md)

## هدف

این سند مشخص می‌کند قابلیت **Import Model** مدل هوش مصنوعی محلی در UI چگونه نمایش داده و اجرا شود.

این قابلیت با **Import File** برای فایل‌های کاربر متفاوت است. Import File فعلاً در UI تعریف نشده است.

## مسیر

```text
تنظیمات
└── هوش مصنوعی
    └── مدل
        ├── مدل فعلی
        ├── Import Model
        │   └── انتخاب فایل مدل از گوشی
        └── مدیریت مدل‌ها
```

## صفحه مدل

صفحه باید ساده، فارسی و RTL باشد و در حالت عادی فقط اطلاعات ضروری را نشان دهد:

```text
مدل هوش مصنوعی
────────────────────────
مدل فعلی
Qwen3-1.7B
GGUF · Q6_K

[ Import Model ]

مدل‌های موجود
────────────────────────
Qwen3-1.7B
GGUF · Q6_K
وضعیت: آماده
```

## Import Model

با انتخاب **Import Model**، File Picker سیستم‌عامل باز می‌شود تا کاربر فایل مدل را از حافظه گوشی انتخاب کند.

UI نباید مسیر یا نام فایل را حدس بزند و نباید مدل را از اینترنت دانلود کند.

پس از انتخاب فایل، قبل از ثبت مدل باید اطلاعات واقعی فایل بررسی شود؛ حداقل:

- نام فایل
- فرمت
- حجم
- قابل شناسایی بودن مدل
- نوع/مشخصات Quantization در صورت قابل استخراج بودن
- سازگاری با Runtime موجود

اگر فایل قابل استفاده نباشد، عملیات نباید موفق اعلام شود و خطای واقعی باید در UI نمایش داده شود.

## وضعیت‌های Import

```text
انتخاب فایل
    ↓
در حال بررسی
    ↓
┌───────────────┐
│ معتبر         │ → آماده ثبت/فعال‌سازی
└───────────────┘

یا

┌───────────────┐
│ نامعتبر       │ → نمایش خطا + امکان انتخاب دوباره
└───────────────┘
```

در صورت وجود مرحله Import/کپی/ثبت واقعی، وضعیت همان Execution باید از داده واقعی Core/Runtime گرفته شود.

**Progress Bar درصدی برای Import در این قرارداد اجباری نیست**؛ اگر Runtime پیشرفت واقعی ارائه کند، نمایش آن باید بر اساس همان داده واقعی باشد.

## مدل هدف اولیه

مدل هدف اولیه ثبت‌شده در قرارداد فعلی:

**Qwen3-1.7B · GGUF · Q6_K**

این مقدار تصمیم طراحی/انتخاب مدل است و UI نباید بدون بررسی فایل واقعی ادعا کند فایل انتخاب‌شده حتماً همین مدل است.

## مدیریت مدل‌ها

برای هر مدل واردشده، اطلاعات خلاصه و وضعیت واقعی نمایش داده شود. جزئیات بیشتر می‌تواند با Expand یا مشاهده جزئیات همان آیتم در دسترس باشد.

نمونه:

```text
Qwen3-1.7B
GGUF · Q6_K
✓ آماده

▼ جزئیات
  نام فایل
  حجم
  فرمت
  Quantization
  وضعیت Runtime
  مسیر ذخیره‌سازی در صورت مجاز بودن نمایش
```

## مدل فعلی

فقط یک مدل نباید صرفاً به دلیل وجود فایل در دستگاه «فعال» تلقی شود. وضعیت فعال بودن باید از وضعیت واقعی Runtime/Model Manager بیاید.

اگر فعال‌سازی مدل یک Action محسوب شود، وضعیت و نتیجه آن باید مطابق قرارداد Workspace/Timeline و Action Trace ثبت شود.

## خطاها

خطاهای کاربرپسند باید فارسی باشند؛ اطلاعات فنی خام و شناسه‌های Execution در مسیر عیب‌یابی قابل مشاهده باشند.

نمونه‌های UI فقط در صورتی نمایش داده شوند که علت واقعی با داده Core مطابقت داشته باشد:

```text
خطا در وارد کردن مدل
فایل انتخاب‌شده قابل استفاده نیست.

[مشاهده جزئیات]
```

«مشاهده جزئیات» باید در صورت وجود Execution/Trace، به گزارش همان Execution در عیب‌یابی برسد.

## قواعد امنیتی و صحت

- فایل مدل فقط پس از انتخاب صریح کاربر وارد می‌شود.
- دانلود خودکار مدل از اینترنت در این قرارداد وجود ندارد.
- هیچ Mock، Placeholder یا وضعیت ساختگی مجاز نیست.
- موفقیت Import فقط با نتیجه واقعی Core/Runtime اعلام می‌شود.
- UI نباید نوع Quantization را از روی نام فایل به‌تنهایی قطعی اعلام کند.
- اطلاعات فنی بزرگ یا کم‌اهمیت نباید نمای اصلی را شلوغ کند.
- تمام متن‌های قابل مشاهده فارسی و RTL هستند؛ مقادیر فنی مانند نام فایل و شناسه‌ها می‌توانند LTR باشند.

## عدم اختلاط با Import File

```text
Import Model
└── تنظیمات → هوش مصنوعی → مدل
    └── فایل مدل برای Runtime محلی

Import File
└── فعلاً در UI تعریف نشده
    └── تصمیم‌گیری مستقل در آینده
```

هر تغییری در این ساختار باید ابتدا در `UI_TREE.md` ثبت و سپس این سند به‌روزرسانی شود.
