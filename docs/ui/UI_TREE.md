**وضعیت:** 🔒 مرجع ساختاری UI v1

## قرارداد مدل محلی

مدل محلی از مسیر **تنظیمات → هوش مصنوعی → مدل** مدیریت می‌شود. ورود مدل با **Import Model** انجام می‌شود و فایل از حافظه گوشی انتخاب می‌شود؛ دانلود مستقیم مدل از داخل برنامه در این قرارداد وجود ندارد.

مدل هدف اولیه ثبت‌شده:

**Qwen3-1.7B · GGUF · Q6_K**

جزئیات Backend، Runtime، Validation، Storage، Lifecycle و قرارداد اتصال UI در [`../core/LOCAL_MODEL_BACKEND.md`](../core/LOCAL_MODEL_BACKEND.md) است. UI نباید قرارداد موازی برای این موارد بسازد.

`Import File` برای منابع/فایل‌های کاربر فعلاً بخشی از UI Tree نیست و تا تصمیم‌گیری مستقل نباید نمایش داده شود.

## قرارداد Workspace

Timeline **مرکز بصری** Workspace است. هیچ پنل Contextual مستقل و ثابتی وجود ندارد. اطلاعات Contextual هر Event داخل Expand همان Event قرار می‌گیرد و Expand می‌تواند چند لایه باشد.

کنترل‌های عملیاتی تطبیقی هستند؛ فقط عملیات واقعی و مجاز همان Action/وضعیت نمایش داده می‌شوند. Progress Bar درصدی برای اجرای جاری وجود ندارد.

## قواعد مرجع

- هر قابلیت UI باید به یک گره مشخص در این درخت نگاشت شود.
- هر کنترل باید پشت Capability/State واقعی Core باشد.
- هیچ قابلیت ساختگی، Mock یا Placeholder نباید وارد درخت اجرایی UI شود.
- اطلاعات فنی فقط در صورت وجود داده واقعی نمایش داده می‌شوند.
- تمام متن‌های قابل مشاهده فارسی و RTL هستند؛ داده ذاتاً فنی می‌تواند LTR باشد.
- `Import Model` فقط برای مدل هوش مصنوعی است و با `Import File` منابع کاربر یکی نیست.
- قرارداد Backend مدل محلی مرجع داده و عملیات است؛ جزئیات UI در اسناد UI باقی می‌ماند.
