# بازطراحی رابط کاربری — نسخه ۲

**وضعیت:** در حال پیاده‌سازی روی شاخه `ui-redesign`
**مبنای تغییر:** درخواست کاربر برای تبدیل Chat به صفحه اصلی، یکپارچه‌سازی تنظیمات، بازطراحی تاریخچه و ناوبری، و اصلاح تأخیر نمایش متن مکالمه صوتی.

## هدف تجربه کاربری

برنامه باید از لحظه ورود مستقیماً محیط گفتگو را نمایش دهد. کاربر برای کارهای روزمره نباید ابتدا از منوها عبور کند؛ مدیریت مدل، Provider، فایل‌های مدل، صدا و تنظیمات پیشرفته در یک مرکز تنظیمات واحد قرار می‌گیرند.

## ناوبری

- مقصد آغازین همیشه `CHAT` است؛ تنها بازشدن از Wake Word می‌تواند مستقیماً وارد مکالمه صوتی شود.
- تاریخچه یک مقصد مستقل است و دیگر فقط به فهرست اخیر Sidebar محدود نیست.
- Sidebar همچنان مسیر دسترسی به مقصدهای ثانویه و گفتگوهای اخیر را فراهم می‌کند.
- تنظیمات صوتی در دسته «صدا»ی صفحه تنظیمات قرار دارد؛ صفحه مکالمه صوتی فقط تجربه مکالمه را ارائه می‌دهد و دکمه تنظیمات آن کاربر را به مرکز تنظیمات می‌برد.
- مقصدهای موجود Workspace، Diagnostics و About حفظ می‌شوند.

## قرارداد تاریخچه و پیام‌ها

- منبع حقیقت پیام‌ها همچنان `ConversationHistoryRepository` است؛ UI نباید یک تاریخچه مستقل و ناسازگار بسازد.
- تاریخچه، عنوان، تعداد پیام و زمان آخرین فعالیت را نمایش می‌دهد.
- جستجو در نسخه فعلی روی گفتگوهای بارگذاری‌شده انجام می‌شود؛ برای دسترسی به سوابق بیشتر باید «بارگذاری گفتگوهای بیشتر» استفاده شود.
- حذف و بازگردانی از Repository فعلی استفاده می‌کند؛ هیچ داده‌ای صرفاً با تغییر UI پاک نمی‌شود.
- پیام‌های صوتی باید همان Conversation ID و همان Repository گفتگو را استفاده کنند تا از صفحه تاریخچه قابل بازکردن و ادامه باشند.

## اصلاح تجربه صوتی

- متن نهایی دستیار در حین دریافت Tokenها، پس از پاک‌سازی کانال‌های غیرقابل نمایش، به‌صورت تدریجی در Transcript ظاهر می‌شود؛ منتظر پایان TTS نمی‌ماند.
- Transcript صوتی با اضافه‌شدن پیام یا تغییر متن، خودکار به آخرین پیام پیمایش می‌کند.
- پاسخ نهایی روی همان ردیف موقت به‌روزرسانی می‌شود تا پیام تکراری ساخته نشود.
- پس از ذخیره پاسخ نهایی در تاریخچه، فهرست گفتگوها و پیش‌نمایش‌ها تازه‌سازی می‌شوند.
- هیچ تغییری نباید محافظت AEC/NS، جلوگیری از ورود صدای TTS به ASR، Barge-in، صف محدود صوت یا رفتار Wake Word را تضعیف کند.

## زبان بصری و تعامل

- زبان برنامه فارسی و RTL باقی می‌ماند؛ داده‌های فنی مانند نام مدل و شناسه‌ها می‌توانند LTR باشند.
- چیدمان ساده، آرام، کم‌هزینه و گفتگو-محور است.
- پیام کاربر به‌صورت حباب سبک نمایش داده می‌شود؛ پاسخ دستیار بر Typography و فضای سفید متکی است.
- فهرست‌های زنده باید آخرین پیام را در دید نگه دارند.
- وضعیت Runtime باید از داده واقعی بیاید؛ UI نباید OpenCL یا GPU را صرفاً از روی انتخاب تنظیمات، فعال فرض کند.
- متن‌های راهنما نباید رفتار صفحه‌کلید یا قابلیت‌های برنامه را اشتباه توصیف کنند.

## مرزهای معماری

- AI Core، Runtime، Model Manager، Provider Store، Voice Controller و Conversation Repository مالک منطق باقی می‌مانند.
- صفحه‌ها فقط از APIهای موجود استفاده می‌کنند؛ منطق مدل یا مجوزها در Composableها بازنویسی نمی‌شود.
- تنظیمات صوتی از همان Host و Store فعلی استفاده می‌کند؛ این تغییر صرفاً جایگاه UI آن‌ها را یکپارچه می‌کند.
- بسته Android همچنان فقط `arm64-v8a` است.
- Local CPU execution و CPU fallback معتبرند؛ GPU صرفاً شتاب‌دهنده اختیاری است.
- هیچ fallback پنهانی بین Local و Provider اضافه نمی‌شود.

## موارد تکمیلی پیشنهادی پس از این مرحله

1. ViewModel/State Holder مستقل برای Chat، History، Settings و Voice؛ کاهش مسئولیت `MainScreen`.
2. ذخیره checkpointهای پاسخ در حال تولید برای بازیابی امن پس از بسته‌شدن برنامه.
3. جستجوی سراسری تاریخچه با Paging در Repository، به‌جای جستجو فقط در فهرست بارگذاری‌شده.
4. عملیات تکمیلی پیام: کپی، ویرایش و ارسال مجدد، بازتولید پاسخ، اشتراک‌گذاری و انتخاب متن.
5. فیلتر و گروه‌بندی تاریخچه بر اساس امروز، دیروز و بازه‌های قدیمی‌تر؛ پشتیبانی از سنجاق و بایگانی فقط پس از تعریف قرارداد Storage.
6. وضعیت خالی، خطا، بارگذاری، بدون مدل، Provider نامعتبر و دسترسی میکروفون با متن و اقدام اصلاحی روشن.
7. آزمون UI در اندازه‌های مختلف صفحه، Font Scale، RTL، IME، TalkBack و چرخه باز/بسته‌شدن برنامه.
8. آزمون واقعی روی دستگاه برای STT/TTS، Wake Word، مکالمه در پس‌زمینه و تأخیر نمایش Transcript.

## معیار پذیرش

- شروع عادی برنامه به صفحه گفتگو منتهی شود.
- تنظیمات مدل، Provider، STT، TTS، Shenava، Laya و شنود دائمی از Settings قابل دسترسی باشند.
- تغییر مقصد و بازگشت از Settings پیام‌های جاری را از بین نبرد.
- تاریخچه گفتگوها قابل جستجو، بازکردن، تغییر نام و حذف/بازگردانی باشد.
- پیام صوتی و متنی یک Conversation واحد را تشکیل دهند.
- متن دستیار در Voice به‌صورت تدریجی و بدون انتظار برای اتمام پخش صوت نمایش داده شود.
- هیچ وضعیت GPU/Backend ساختگی نمایش داده نشود.
- تست‌ها و CI سبز باشند و آزمون واقعی دستگاه برای تأیید تجربه صوتی انجام شود.
