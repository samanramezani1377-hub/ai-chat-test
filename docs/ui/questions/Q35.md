# سؤال ۳۵ — نمایش نتیجه و Preview در فضای کار

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — ترکیبی، منطبق با ساختار Timeline و Expand**

نتیجه هر Action باید به‌عنوان بخشی از همان آیتم در **Timeline مرکزی Workspace** نمایش داده شود. نمای پیش‌فرض خلاصه و مینیمال است و اطلاعات بیشتر با **Expand از پایین همان Action** قابل مشاهده است.

```text
✓ ایجاد فایل
  انجام شد
  ایجاد فایل · 1.2s · 14 KB

  ▼ جزئیات
     Preview
     Result
     اطلاعات پردازشی
     مشاهده جزئیات →
```

### قواعد

- Preview در صورت وجود، نمای اولیه و خوانای نتیجه باشد.
- خروجی‌های بزرگ نباید Timeline را شلوغ کنند؛ در حالت عادی خلاصه/Preview نمایش داده شود.
- جزئیات کامل با Expand از پایین همان Action باز شود.
- Before/After فقط برای Actionهایی که واقعاً داده‌ای را تغییر داده‌اند و مقایسه واقعی قابل ارائه است نمایش داده شود.
- کنترل‌های Contextual همان Action طبق Q32 نمایش داده شوند.
- اطلاعات پردازشی ثانویه طبق Q33 کوچک‌تر و کم‌رنگ باشند.
- «مشاهده جزئیات» مسیر Context همان Action/Execution را حفظ کند و به مشخصات درخواست یا گزارش عیب‌یابی متناظر برسد.
- Result و Preview باید از نتیجه واقعی Execution گرفته شوند؛ Mock، مقدار تخمینی یا خروجی ساختگی مجاز نیست.

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.
