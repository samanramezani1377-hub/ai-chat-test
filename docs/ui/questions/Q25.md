# سؤال ۲۵ — دسترسی به اطلاعات مدل و Inference

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — ترکیبی**

اطلاعات مدل و Inference به‌صورت خلاصه در Header قابل مشاهده هستند و جزئیات کامل‌تر از مسیرهای مربوط به **تنظیمات / فضای کار** در دسترس قرار می‌گیرند؛ بدون تکرار غیرضروری اطلاعات.

```text
Header
└── Runtime
    └── خلاصه مدل و Inference

فضای کار / تنظیمات
└── جزئیات کامل مدل و Inference
```

### اطلاعات مدل

اطلاعات واقعی مدل فعال، از جمله وضعیت آن، باید قابل مشاهده باشد. وضعیت‌های مرتبط با بارگذاری مدل مانند Loaded، Loading، Unloaded و Error باید به شکل فارسی در UI نمایش داده شوند.

### اطلاعات Inference

اطلاعات اصلی مربوط به اجرای Inference باید در بخش جزئیات قابل دسترسی باشند و با اطلاعات Performance که در Q23 و Q24 تعریف شده‌اند اشتباه یا بی‌دلیل تکرار نشوند.

### اصل عدم تکرار

Header برای **خلاصه و وضعیت سریع** است؛ فضای کار و تنظیمات برای **جزئیات** هستند.

تمام اطلاعات باید از Runtime واقعی گرفته شوند و نمایش مقدار ساختگی یا Mock مجاز نیست.

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.

## قفل UI

این تصمیم بخشی از UI Contract است و قبل از کدنویسی نهایی قفل شده است.
