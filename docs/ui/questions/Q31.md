# سؤال ۳۱ — جزئیات Workspace

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — ترکیبی، با Expand در همان محل**

نمای اصلی Workspace باید یک Timeline جمع‌وجور و مینیمال باشد؛ جزئیات هر مرحله، Action، Tool Result، Verification و Preview/Result در حالت عادی جمع‌شده باشند و با کلیک روی همان مورد، **از پایین همان مورد Expand** شوند.

```text
فضای کار
│
├── ✓ آماده‌سازی
│
├── ✓ Action
│     └── ▼ جزئیات
│          ├── وضعیت
│          ├── نتیجه
│          ├── Preview / خروجی
│          └── اطلاعات مرتبط
│
├── ⏳ Verification
│     └── ▼ جزئیات
│
└── ✓ نتیجه نهایی
```

### اصل طراحی

- Workspace در حالت عادی شلوغ نشود.
- جزئیات از پایین همان آیتم Expand شوند و کاربر برای دیدن اطلاعات به صفحه دیگری منتقل نشود.
- اطلاعات نمایش‌داده‌شده باید فقط از داده واقعی اجرای همان مرحله تهیه شوند.
- مسیر «مشاهده جزئیات» که طبق Q28/Q30 تعریف شده، برای ورود مستقیم به مشخصات درخواست یا گزارش عیب‌یابی متناظر همچنان جداگانه حفظ می‌شود.
- Preview و Result مربوط به همان مرحله باید در صورت وجود، داخل جزئیات همان مرحله قابل مشاهده باشند.

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.

## قفل UI

این تصمیم بخشی از UI Contract است و قبل از کدنویسی نهایی قفل شده است.
