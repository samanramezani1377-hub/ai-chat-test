# سؤال ۳۸ — جایگاه مرکز خطاها

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — ترکیبی**

خطا باید در همان Contextی که اتفاق افتاده قابل مشاهده باشد، اما فهرست و گزارش کامل خطاها نیز از داخل بخش **«عیب‌یابی»** در دسترس باشد.

### نمایش در Context

اگر خطایی در Chat یا اجرای یک Action رخ دهد، خلاصه خطا همان‌جا نمایش داده می‌شود و کاربر می‌تواند با انتخاب **«مشاهده جزئیات»** وارد مسیر جزئیات مربوط به آن شود.

```text
گفت‌وگو
└── ✕ خطا در اجرای Action
      └── مشاهده جزئیات
             ↓
          فضای کار
             ↓
          عیب‌یابی
```

### دکمه مستقل خطاها در عیب‌یابی

داخل صفحه **«عیب‌یابی»** باید یک **دکمه/مسیر مستقل «خطاها»** وجود داشته باشد تا کاربر بتواند مستقیماً فهرست خطاها و گزارش‌های ثبت‌شده را مشاهده کند.

```text
عیب‌یابی
├── خطاها
├── Trace
├── Recovery
└── سایر ابزارهای عیب‌یابی
```

این «خطاها» یک مقصد مستقل در Sidebar نیست؛ بلکه **زیرمجموعه مستقل داخل عیب‌یابی** است.

## اصل تفکیک

```text
Context خطا
└── خلاصه + مشاهده جزئیات

عیب‌یابی
└── خطاها
    └── فهرست و گزارش کامل
```

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.
