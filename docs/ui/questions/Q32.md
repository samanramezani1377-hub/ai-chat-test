# سؤال ۳۲ — کنترل‌های Workspace

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — کامل، اما تطبیقی و Context-aware**

همه کنترل‌های ممکن نباید به‌صورت ثابت و هم‌زمان نمایش داده شوند. Workspace باید بر اساس **Action واقعی و وضعیت همان لحظه** فقط کنترل‌های مجاز و مرتبط را نمایش دهد.

```text
Workspace
└── Action
    ├── وضعیت / نتیجه
    ├── کنترل‌های مجاز همان لحظه
    │   ├── تأیید
    │   ├── رد
    │   ├── ویرایش (فقط اگر واقعاً قابل ویرایش باشد)
    │   └── لغو (فقط اگر واقعاً قابل لغو باشد)
    ├── مشاهده جزئیات
    └── جزئیات / Preview با Expand
```

### قواعد

- **تأیید و رد** برای درخواست‌هایی که Core واقعاً اجازه آن را می‌دهد، از Workspace قابل انجام هستند؛ مطابق Q30.
- **ویرایش** فقط زمانی نمایش داده شود که Action/داده واقعاً قابلیت ویرایش داشته باشد.
- **لغو** فقط زمانی نمایش داده شود که اجرای واقعی قابلیت لغو داشته باشد.
- کنترل نامرتبط یا غیرمجاز نباید نمایش داده شود.
- کنترل‌ها باید با وضعیت فعلی Action تطبیق پیدا کنند؛ پس از تغییر وضعیت، کنترل‌های نامعتبر حذف/غیرفعال شوند.
- «مشاهده جزئیات» جدا از کنترل‌های عملیاتی باقی می‌ماند و اطلاعات همان درخواست را باز می‌کند.
- جزئیات Preview/Result طبق Q31 از پایین همان آیتم Expand می‌شوند.
- هیچ کنترل UI نباید قابلیت فرضی یا Mock را به کاربر القا کند.

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.
