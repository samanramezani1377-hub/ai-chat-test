# Q02 — Header & Primary Navigation

**Status:** 🔒 Decided

## Decision

The application uses a compact two-sided header.

```text
┌──────────────────────────────────────────────┐
│ ┌──────────────────┐  ● Ready        ┌────┐ │
│ │ Chat │ Work │ ⋯  │                 │ ☰  │ │
│ └──────────────────┘                 └────┘ │
└──────────────────────────────────────────────┘
```

## Left — Quick Navigation

A compact navigation group occupies less than half of the header width:

- **Chat** — primary conversation surface.
- **Work** — Workspace.
- **⋯** — secondary quick menu.

The group must remain compact and must not visually dominate the header.

### Secondary Quick Menu

The `⋯` menu contains secondary utility destinations:

- Logs
- Settings

These are intentionally separated from the primary navigation.

## Center — Local AI Runtime Status

A small status indicator is displayed between the left navigation group and the right sidebar button.

The status consists of a semantic label and a small indicator dot.

### Statuses

| Status | Meaning |
|---|---|
| ● Ready | Local AI runtime is ready to accept work. |
| ● در حال کار | Local AI runtime is actively processing work. |
| ● Generating | The assistant is actively generating a response. |
| ● خارج از دسترس | The local AI runtime is unavailable because it is not functioning correctly. |
| ● Error | A runtime or application error has occurred. |

**Important:** `Connecting` and `Offline` are not used as the primary user-facing labels for the local runtime. The wording must describe the actual state in user terms, especially **در حال کار** and **خارج از دسترس**.

Color is a secondary visual signal only. Every state must remain understandable from its text label and/or accessible semantic description.

The exact status colors are defined later in the Design System documentation.

## Right — Main Sidebar

A circular hamburger button is positioned at the upper-right side of the header.

```text
╭────╮
│ ☰  │
╰────╯
```

Opening this button reveals the main application sidebar.

The following belong to the sidebar rather than the header:

- New Conversation
- Conversation History
- Current Conversation
- Workspace
- Diagnostics
- About

The sidebar is the main structural navigation surface; it must not be duplicated as multiple header controls.

## Header Responsibilities

The header is responsible for exactly three groups:

1. Quick navigation on the left.
2. Local AI/runtime status in the center.
3. Main sidebar access on the right.

No additional permanent controls are required at this stage.

## Explicit Exclusions

The header must not permanently contain:

- Large application title.
- Large logo.
- Search field.
- New Conversation button.
- Token/latency information.
- Debug information.
- Large status panels.
- Permanent bottom navigation.

These may be introduced later only through an explicit specification change.

## Responsive Behavior

The left group remains compact on narrow screens. The status indicator must yield space before the primary navigation or sidebar control becomes unusable.

If space becomes constrained, labels may use the established responsive strategy from the Design System, but the three primary controls and sidebar access must remain discoverable.

## Accessibility

- Every control has an accessible semantic label.
- The hamburger button must not rely on its visual icon alone.
- The `⋯` button must have a descriptive accessibility label.
- Runtime status must be exposed as meaningful text/semantics.
- Status meaning must not depend on color alone.

## Consequences

This decision establishes the App Shell/header navigation model and must be reflected in `NAVIGATION.md`, `DESIGN_SYSTEM.md`, `STATES.md`, and `SCREENS.md` before UI implementation begins.
