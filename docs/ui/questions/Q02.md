# سؤال ۲ — ساختار هدر و ناوبری اصلی

**وضعیت:** 🔒 تصمیم‌گیری شده

## تصمیم

هدر یک ساختار فشرده و دوطرفه دارد و دقیقاً سه ناحیه اصلی را در خود جای می‌دهد:

```text
┌──────────────────────────────────────────────────────┐
│ [ گفت‌وگو │ کار │ ⋯ ]    ● آماده      مدل محلی   [ ☰ ] │
└──────────────────────────────────────────────────────┘
```

> براکت‌ها در این مستند فقط برای نمایش ساختار هستند و نباید به‌صورت UI نمایش داده شوند.

## سمت چپ — ناوبری سریع

گروه سمت چپ کمتر از نصف عرض هدر را اشغال می‌کند و شامل موارد زیر است:

- **گفت‌وگو** — مقصد اصلی گفتگو.
- **کار** — ورود به فضای کار.
- **⋯** — منوی جانبی شامل لاگ و تنظیمات.

صفحه فعال با **یک خط ظریف زیر همان گزینه** مشخص می‌شود.

## منوی سه‌نقطه

منوی `⋯` یک منوی کوچک و Premium است که از همان ناحیه باز می‌شود و شامل:

- لاگ
- تنظیمات

ظاهر آن باید با منوی عملیات گفت‌وگو در Sidebar یکسان باشد: Surface نرم، گوشه‌های گرد، Shadow ظریف و Motion کوتاه.

## مرکز — وضعیت Runtime محلی

بین گروه سمت چپ و دکمه همبرگری سمت راست، وضعیت Runtime محلی نمایش داده می‌شود.

نمایش دوخطی است:

```text
● آماده
مدل محلی
```

ارتفاع کل این بخش باید با ارتفاع دکمه‌های هدر برابر و کاملاً هم‌تراز باشد. وضعیت اصلی وزن بصری بیشتری از نام Runtime دارد.

وضعیت‌های مصوب:

- **آماده**
- **در حال کار**
- **در حال تولید**
- **خارج از دسترس**
- **خطا**

هر وضعیت رنگ مخصوص خود را دارد؛ در وضعیت‌های فعالیت Runtime، نقطه با Pulse ظریف نمایش داده می‌شود.

## سمت راست — Sidebar اصلی

دکمه گرد همبرگری در سمت راست هدر قرار دارد و Sidebar اصلی را باز می‌کند.

Sidebar از سمت راست وارد می‌شود و در موبایل، تبلت و صفحه بزرگ رفتار تطبیقی دارد.

## مسئولیت هدر

هدر فقط مسئول این سه ناحیه است:

۱. ناوبری سریع: گفت‌وگو / کار / ⋯
۲. وضعیت Runtime محلی
۳. دسترسی به Sidebar اصلی

کنترل دائمی دیگری در هدر لازم نیست.

## موارد خارج از هدر

موارد زیر نباید به‌صورت کنترل دائمی در هدر قرار بگیرند:

- گفت‌وگوی جدید
- تاریخچه گفتگوها
- خطاها
- درباره برنامه
- اطلاعات Debug
- Token و Latency
- پنل‌های بزرگ وضعیت

این موارد در Sidebar یا سطوح تخصصی خود قرار می‌گیرند.

## زبان و جهت

**کل UI فارسی و راست‌چین (RTL) است.** داده‌های ذاتاً فنی مانند نام مدل، کد، URL و شناسه فنی تنها استثنا هستند و باید با چیدمان LTR مناسب درون ساختار RTL نمایش داده شوند.
