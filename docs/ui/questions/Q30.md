# سؤال ۳۰ — Verification و مداخله کاربر

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — ترکیبی، با تأیید/رد مستقیم در Workspace**

درخواست‌های Verification باید در **فضای کار** قابل مدیریت باشند، اما جزئیات درخواست از عملیات تأیید/رد جدا باشد.

```text
فضای کار
┌─────────────────────────────────┐
│ درخواست Verification            │
│ ⏳ نیازمند تأیید                │
│                                 │
│ [ تأیید ]   [ رد ]              │
│                                 │
│ مشاهده جزئیات ←                 │
└─────────────────────────────────┘
                 │
                 ▼
مشخصات و توضیحات همان درخواست
```

### رفتار UI

- **تأیید** مستقیماً از Workspace قابل انجام است.
- **رد** مستقیماً از Workspace قابل انجام است.
- گزینه **«مشاهده جزئیات»** از Workspace باید مشخصات و توضیحات کامل **همان درخواست Verification** را باز کند.
- برای درخواست‌های حساس، گزارش کامل Verification و اطلاعات مرتبط در عیب‌یابی نیز قابل دسترسی باشد.
- عملیات تأیید/رد نباید کاربر را صرفاً برای انجام عمل به عیب‌یابی منتقل کند.
- مسیر مشاهده جزئیات باید Context همان درخواست و شناسه آن را حفظ کند.
- اگر اطلاعات یا گزارش واقعی درخواست در سیستم موجود نباشد، UI نباید اطلاعات ساختگی نمایش دهد.

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.
