# سؤال ۳۷ — رابط کاربری تأیید Action حساس

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

تأیید Actionها دو سطح دارد و هر دو سطح باید امکان **مشاهده جزئیات از مسیر فضای کار** را داشته باشند.

### ۱. تأیید معمولی

- با یک کارت معمولی و هماهنگ با UI نمایش داده می‌شود.
- کارت خلاصه‌ای از Action و وضعیت آن را نشان می‌دهد.
- گزینه **«مشاهده جزئیات»** همیشه در دسترس است.
- «مشاهده جزئیات» کاربر را به جزئیات کامل همان Action در **فضای کار** می‌رساند.
- کنترل‌های اصلی شامل **تأیید** و **رد** هستند.

### ۲. تأیید حساس

Actionهای حساس باید از نظر بصری **به‌وضوح با تأیید معمولی متفاوت** باشند تا اهمیت آن‌ها برای کاربر قابل تشخیص باشد.

کارت تأیید حساس باید:

- خلاصه عملیات را نمایش دهد.
- دلیل انجام عملیات را مشخص کند.
- اطلاعاتی را که تحت تأثیر قرار می‌گیرند مشخص کند.
- نتیجه مورد انتظار را توضیح دهد.
- گزینه **«مشاهده جزئیات»** داشته باشد.
- با انتخاب «مشاهده جزئیات» به **فضای کار** منتقل شود.
- یک **گزارش فارسی و قابل فهم از عملیات** ارائه کند.

### گزارش فارسی عملیات حساس

گزارش باید برای کاربر قابل فهم باشد و حداقل این موارد را پوشش دهد:

```text
چه کاری قرار است انجام شود؟
چرا قرار است انجام شود؟
چه اطلاعاتی تحت تأثیر قرار می‌گیرند؟
نتیجه مورد انتظار چیست؟
وضعیت فعلی عملیات چیست؟
```

### تأیید نهایی

برای عملیات حساس، پس از بررسی گزارش و جزئیات، یک **پنجره تأیید نهایی** نمایش داده می‌شود.

```text
┌─────────────────────────────┐
│       تأیید عملیات حساس     │
│                             │
│  گزارش فارسی عملیات         │
│  جزئیات قابل مشاهده         │
│                             │
│ [ لغو ]     [ تأیید نهایی ] │
└─────────────────────────────┘
```

این پنجره آخرین مرحله قبل از اجرای Action حساس است.

## اصل تفکیک

```text
کارت تأیید
    ↓
مشاهده جزئیات
    ↓
فضای کار
    ↓
گزارش فارسی عملیات حساس
    ↓
تأیید نهایی
    ↓
اجرای Action
```

## زبان و راست‌چین

تمام متن‌ها و اجزای این جریان باید فارسی و راست‌چین (RTL) باشند.
