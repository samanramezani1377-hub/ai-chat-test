# سؤال ۲۸ — تعامل با Trace و خطاها

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — کامل، با دسترسی مستقیم از Workspace به گزارش عیب‌یابی همان اجرا**

در بخش عیب‌یابی، کاربر با Trace و خطاهای یک Execution تعامل کامل دارد؛ شامل مشاهده، کپی، Retry و Verification، همراه با نمایش واضح وضعیت هر Action و عملی که برای آن مجاز است.

علاوه بر این، هر مورد مربوط به یک Action در **فضای کار** باید یک گزینه **«مشاهده جزئیات»** داشته باشد. انتخاب این گزینه مستقیماً کاربر را به **عیب‌یابی و گزارش همان Action/Execution** می‌برد؛ نه به صفحه عمومی عیب‌یابی.

```text
فضای کار
└── Action
    ├── وضعیت
    ├── نتیجه
    └── مشاهده جزئیات
          │
          ▼
عیب‌یابی
└── گزارش همان Action / Execution
    ├── نتیجه اجرا
    ├── Trace مرتبط
    ├── خطاهای مرتبط
    ├── جزئیات Verification
    └── Recovery / Retry
```

### تعاملات عیب‌یابی

- مشاهده جزئیات Trace و خطاها
- کپی متن و جزئیات Trace/خطا
- Retry برای Actionهایی که واقعاً قابلیت Retry دارند
- Verification برای مواردی که نیازمند Verification هستند
- نمایش واضح وضعیت Action و عملیات مجاز
- حفظ ارتباط بین Action، `executionId` و گزارش عیب‌یابی متناظر

### اصل Deep Link

«مشاهده جزئیات» در Workspace باید Context اجرای انتخاب‌شده را حفظ کند و کاربر را مستقیماً روی گزارش متناظر در Diagnostics قرار دهد. کاربر نباید مجبور باشد دوباره Execution یا Action را در عیب‌یابی پیدا کند.

اگر گزارش متناظر در سیستم موجود نباشد، UI نباید گزارش یا جزئیات ساختگی ایجاد کند و باید این وضعیت را به‌صورت واقعی و قابل تشخیص نمایش دهد.

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.
