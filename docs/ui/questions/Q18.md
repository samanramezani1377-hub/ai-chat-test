# سؤال ۱۸ — Composer پیام

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم

**گزینه D — Composer شناور تطبیقی**

Composer در پایین صفحه به‌صورت Floating طراحی می‌شود و اندازه و ابعاد آن بر اساس فضای نمایش تطبیق پیدا می‌کند.

### موبایل

- شناور و جمع‌وجور.
- فاصله مناسب از لبه پایین و کناره‌ها.
- مناسب برای تعامل لمسی.

### تبلت

- کمی بزرگ‌تر از موبایل.
- فضای داخلی و عرض متناسب با صفحه.

### دسکتاپ

- Floating با عرض محدود و مرکزگرا.
- نباید تمام عرض صفحه را بی‌دلیل اشغال کند.

## ارتفاع

Composer با افزایش متن می‌تواند رشد کند، اما باید **حداکثر ارتفاع مشخص** داشته باشد.

پس از رسیدن به سقف ارتفاع، متن داخل Composer اسکرول می‌شود و کل Layout صفحه نباید به‌صورت نامحدود جابه‌جا شود.

## زبان و راست‌چین

- Placeholder و متن‌های Composer فارسی و راست‌چین (RTL) هستند.
- محل Cursor و ورود متن با RTL سازگار است.

## زبان بصری

- Surface Premium.
- Radius هماهنگ با Design System.
- Shadow ظریف.
- بدون Blur سنگین.
- بدون شلوغی بصری.
- Composer باید بخشی طبیعی از فضای گفتگو باشد، نه یک پنل سنگین.

## آمادگی آینده

ساختار Composer باید طوری باشد که ابزارهای آینده مانند پیوست، میکروفون یا قابلیت‌های دیگر بتوانند بدون تغییر اساسی معماری UI اضافه شوند؛ اما در این مرحله هیچ ابزار اضافه‌ای به‌صورت الزامی وارد UI نمی‌شود.
