# سؤال ۴ — ارتفاع و اندازه هدر

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم

**گزینه C — کمی بزرگ‌تر و Premium**

هدر در نسخه فعلی باید کمی بزرگ‌تر و دارای فضای تنفسی مناسب باشد تا دکمه‌ها، وضعیت Runtime و گروه Navigation بدون فشردگی نمایش داده شوند و هدر به‌عنوان یک Surface مستقل و Premium دیده شود.

## الزامات طراحی

- ارتفاع هدر از حالت فشرده بیشتر باشد.
- دکمه‌های اصلی فضای لمسی مناسب داشته باشند.
- فاصله داخلی و بین کنترل‌ها کافی باشد.
- افزایش ارتفاع نباید باعث کاهش غیرضروری فضای محتوای Chat شود.
- طراحی باید با Header شناور/سطحی Q03 هماهنگ باشد.
- تمام متن‌های قابل مشاهده فارسی و راست‌چین (RTL) باشند.

## آمادگی برای تغییر در کد

اگر در تست واقعی مشخص شد که اندازه گزینه C بیش از حد بزرگ است، پیاده‌سازی باید از ابتدا به شکلی ساختاریافته باشد که **بدون تغییر معماری یا بازطراحی UI** بتوان اندازه هدر را با یک تغییر کدی ساده به اندازه استاندارد گزینه B کاهش داد.

این قابلیت یک تنظیم کاربری نیست و **نباید در Settings قرار بگیرد**. انتخاب فعلی همچنان C است؛ فقط ساختار کد باید امکان تغییر ساده بین اندازه‌های تعریف‌شده را حفظ کند.

## محدودیت

این تصمیم به معنی پیاده‌سازی فعلی گزینه B نیست و نباید باعث ایجاد UI دوحالته برای کاربر شود. نسخه رسمی UI در زمان اجرا همان گزینه C است.

## پیامدها

- اندازه Header باید به‌صورت یک مقدار/توکن قابل تغییر در Design System تعریف شود.
- Componentهای Header نباید به ارتفاع فعلی به‌صورت پراکنده وابسته شوند.
- تغییر C به B در آینده باید با تغییر محدود در تعریف اندازه انجام‌پذیر باشد.
- این آمادگی نباید کیفیت بصری، Performance یا تست‌پذیری را کاهش دهد.
