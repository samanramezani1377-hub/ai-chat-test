# سؤال ۳۳ — ساختار کلی صفحه فضای کار

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**Timeline محور — با Timeline در مرکز صفحه**

فضای کار حول یک Timeline مرکزی ساخته می‌شود و اطراف آن فقط اطلاعات و ابزارهای مکمل و کم‌حجم قرار می‌گیرند.

```text
┌─────────────────────────────────────────────────────┐
│                 نوار بالای Workspace                │
├───────────────────────┬─────────────────────────────┤
│ خلاصه اجرای جاری      │                             │
│ وضعیت                 │       TIMELINE مرکزی        │
│ مرحله فعلی            │                             │
│ زمان سپری‌شده          │ ● شروع اجرا                 │
│                       │ ├── ✓ Action               │
│                       │ ├── ⏳ Verification        │
│                       │ ├── ✓ Result               │
│                       │ └── ...                     │
├───────────────────────┴─────────────────────────────┤
│                 اطلاعات کمکی کم‌حجم                 │
└─────────────────────────────────────────────────────┘
```

### نقش بخش‌ها

- **Timeline مرکزی:** ستون فقرات و مرکز بصری Workspace و محل نمایش جریان واقعی اجرای کار.
- **خلاصه اجرای جاری:** اطلاعات کلی و کم‌حجم اجرای فعلی؛ نباید با Timeline رقابت کند.
- **اطلاعات کمکی:** فقط اطلاعات ثانویه‌ای که ارزش نمایش دائمی دارند.
- **پنل Contextual مستقل:** وجود ندارد؛ اطلاعات Contextual داخل Expand همان Event قرار می‌گیرد.

### اطلاعات پردازشی کنار هر Action

هر Action در Timeline در حالت عادی ساده و مینیمال است. اطلاعات اصلی شامل نام Action، وضعیت و نتیجه/عنوان خطا است.

اطلاعات پردازشی واقعی و ثانویه در خطی کوچک‌تر و کم‌رنگ‌تر کنار/زیر Action نمایش داده می‌شوند؛ مانند زمان اجرا، حجم داده، تعداد توکن یا مرحله اجرا، **فقط در صورتی که Core واقعاً آن Metric را ارائه کند**.

```text
● ارسال فایل
  ✓ انجام شد

  ایجاد فایل · 1.2s · 14 KB
```

### Expand لایه‌ای

جزئیات هر Event از پایین همان Event باز می‌شود و می‌تواند چند لایه داشته باشد:

```text
Action
├── خلاصه وضعیت
├── ▼ جزئیات
│   ├── ▼ اطلاعات درخواست
│   ├── ▼ پردازش و Trace همان Event
│   ├── ▼ Preview / Result
│   ├── ▼ Verification / Evidence در صورت وجود
│   ├── ▼ Recovery در صورت وجود
│   └── مشاهده جزئیات → عیب‌یابی همان Execution
└── کنترل‌های مجاز همان لحظه
```

### قواعد مهم

- Timeline مرکز توجه صفحه است.
- Layout نباید به یک داشبورد شلوغ تبدیل شود.
- جزئیات هر آیتم طبق Q31 از پایین همان آیتم Expand می‌شود.
- کنترل‌های Action طبق Q32 تطبیقی و متناسب با وضعیت واقعی Action هستند.
- «مشاهده جزئیات» Context همان Action/Execution را حفظ می‌کند و به گزارش متناظر در عیب‌یابی می‌رود.
- Action Trace در Timeline ادغام می‌شود و Timeline جداگانه برای Trace ایجاد نمی‌شود.
- Metric یا اطلاعاتی که Core گزارش نمی‌کند نباید با مقدار تخمینی، Mock یا ساختگی نمایش داده شود.
- **Progress Bar درصدی در Workspace وجود ندارد.**
