# سؤال ۲۳ — محل نمایش عملکرد Runtime

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه D با گسترش مسیر ذخیره‌سازی**

Metricهای مربوط به اجرای فعلی در **«فضای کار»** نمایش داده می‌شوند و تاریخچه عملکرد نیز در همان مسیر قابل دسترسی خواهد بود.

علاوه بر Workspace، اطلاعات عملکردی اجرای واقعی باید در بخش **«عیب‌یابی»** نیز در محل مربوط به Performance نگهداری و قابل بررسی باشد.

```text
اجرای Runtime
│
├── فضای کار
│   ├── اجرای فعلی
│   │   └── Metricهای عملکرد Runtime / Inference
│   └── تاریخچه عملکرد
│
└── عیب‌یابی
    └── عملکرد
        └── اطلاعات و سوابق عملکردی ثبت‌شده
```

### اصل طراحی

- **Workspace** محل اصلی مشاهده عملکرد اجرای فعلی و بررسی نتیجه همان اجرا است.
- **عیب‌یابی** محل بررسی و نگهداری اطلاعات عملکردی برای تحلیل و عیب‌یابی است.
- ثبت اطلاعات در عیب‌یابی نباید باعث شلوغ‌شدن Chat یا Header شود.
- یک داده عملکردی نباید صرفاً به دلیل نمایش در Workspace از سوابق عیب‌یابی حذف شود.
- Measurement واقعی مستقل از Visibility UI باقی می‌ماند.
- اگر Metric در Runtime/دستگاه قابل اندازه‌گیری نباشد، نباید مقدار ساختگی یا Mock نمایش داده شود.
