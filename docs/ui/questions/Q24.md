# سؤال ۲۴ — تاریخچه و خروجی عملکرد

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه E — کامل، با جزئیات Expand در همان فهرست**

تاریخچه عملکرد در Workspace نمایش داده می‌شود و امکانات **مقایسه اجراها، خروجی گرفتن گزارش و فیلتر و مشاهده جزئیات هر اجرا** نیز فراهم است.

هر اجرای تاریخچه به‌صورت یک مورد خلاصه نمایش داده می‌شود. با کلیک روی همان مورد، جزئیات **از پایین همان مورد Expand** می‌شود و کاربر بدون ترک فهرست، جزئیات را همان‌جا مشاهده می‌کند.

```text
فضای کار
└── عملکرد
    ├── اجرای فعلی
    ├── تاریخچه اجراها
    │   ├── اجرای ۱  ✓
    │   │   └── ▼ جزئیات اجرا
    │   │       ├── اطلاعات اجرا
    │   │       ├── Runtime / Inference
    │   │       ├── Metricهای قابل نمایش
    │   │       ├── Actionها
    │   │       ├── خطاها / Recovery
    │   │       └── خروجی
    │   ├── اجرای ۲  ✓
    │   └── اجرای ۳  ✕
    ├── فیلتر
    ├── انتخاب چند اجرا
    ├── مقایسه
    └── خروجی گزارش
```

### رفتار Expand

- حالت پیش‌فرض هر اجرا جمع‌شده است.
- با کلیک روی اجرا، جزئیات **از پایین همان کارت/ردیف** باز می‌شود.
- بازشدن جزئیات نباید کاربر را به صفحه دیگری منتقل کند.
- با کلیک مجدد، جزئیات بسته می‌شود.
- جزئیات باید با Visibility تنظیم‌شده برای Metricها هماهنگ باشد.
- اطلاعات نمایش‌داده‌شده باید از داده واقعی همان اجرا تهیه شود؛ مقدار ساختگی یا Mock مجاز نیست.

### ذخیره‌سازی سوابق

سوابق عملکردی علاوه بر Workspace، در بخش مربوط به Performance در **عیب‌یابی** نیز نگهداری می‌شوند.

## اصل طراحی

- تاریخچه فقط یک فهرست خام نیست؛ هر اجرا جزئیات قابل مشاهده و Expand در همان محل دارد.
- مقایسه باید امکان بررسی چند اجرای قبلی را فراهم کند.
- Export باید گزارش عملکرد واقعی را تولید کند.
- فیلترها برای محدودکردن تاریخچه اجراها در نظر گرفته می‌شوند.
- Workspace برای بررسی عملیاتی و عیب‌یابی برای تحلیل عمیق‌تر استفاده می‌شود.
