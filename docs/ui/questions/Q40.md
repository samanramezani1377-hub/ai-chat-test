# سؤال ۴۰ — کنترل Visibility معیارهای Performance

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم نهایی

**گزینه D — فهرست + گروه‌بندی**

کنترل نمایش معیارهای عملکرد در مسیر **تنظیمات → عملکرد** قرار می‌گیرد.

دو سطح Visibility وجود دارد:

1. **Visibility دسته** — هر دسته عملکردی یک کنترل مستقل برای فعال/مخفی‌کردن کل دسته دارد.
2. **Visibility Metric** — هر Metric داخل دسته نیز کنترل مستقل برای فعال/مخفی‌شدن دارد.

```text
تنظیمات
└── عملکرد
    ├── ▼ مدل                    👁 فعال
    │   ├── زمان پردازش          👁 فعال
    │   └── مصرف حافظه           ○ مخفی
    │
    ├── ▶ استنتاج                ○ مخفی
    ├── ▶ دستگاه                 👁 فعال
    ├── ▶ عامل                   👁 فعال
    └── ▶ شبکه                   👁 فعال
```

### رفتار Visibility

- مخفی‌کردن یک **دسته** باعث می‌شود Metricهای آن دسته در UI نمایش داده نشوند.
- مخفی‌کردن دسته، وضعیت Visibility تک‌تک Metricهای داخل آن را حذف یا بازنویسی نمی‌کند.
- وقتی دسته دوباره فعال شود، هر Metric وضعیت Visibility قبلی خودش را حفظ می‌کند.
- مخفی‌کردن یک Metric فقط همان Metric را از UI پنهان می‌کند.
- Visibility فقط روی **نمایش UI** اثر دارد و باعث توقف Measurement واقعی نمی‌شود.

### اصل مهم

Measurement واقعی Metricها مستقل از Visibility UI ادامه پیدا می‌کند.

اگر یک Metric در Runtime/دستگاه قابل اندازه‌گیری نباشد، نباید مقدار ساختگی یا Mock نمایش داده شود.

## زبان و راست‌چین

تمام متن‌ها و اجزای این مسیر باید فارسی و راست‌چین (RTL) باشند.
