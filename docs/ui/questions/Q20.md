# سؤال ۲۰ — رفتار ورود متن و ارسال

**وضعیت:** 🔒 تصمیم‌گیری شد

## تصمیم

**B — تطبیقی با رفتار اختصاصی دسکتاپ و موبایل**

### دسکتاپ

رفتار کلیدها به شکل زیر است:

- `Enter` → ایجاد خط جدید
- `Shift + Enter` → ارسال پیام

در نتیجه Enter به‌تنهایی هرگز پیام را ارسال نمی‌کند و برای نوشتن متن چندخطی استفاده می‌شود.

### موبایل

- ارسال فقط از طریق **دکمه ارسال** انجام می‌شود.
- فشردن Enter/Return روی کیبورد موبایل **نباید پیام را ارسال کند**.
- Enter روی موبایل برای ایجاد خط جدید استفاده می‌شود.

## هدف UX

این رفتار باید احتمال ارسال ناخواسته پیام را کاهش دهد و برای پیام‌های چندخطی مناسب باشد.

## زبان و راست‌چین

Composer و تمام متن‌های قابل مشاهده فارسی و راست‌چین (RTL) هستند.

## Accessibility

- رفتار کلیدها باید در رابط کاربری قابل فهم و قابل کشف باشد.
- ارسال نباید فقط به یک میانبر صفحه‌کلید وابسته باشد؛ دکمه ارسال همیشه در دسترس است.
- کاربران موبایل باید بتوانند بدون استفاده از میانبر صفحه‌کلید پیام را ارسال کنند.

## آمادگی پیاده‌سازی

رفتار Keyboard/IME باید به‌صورت Responsive و بر اساس Platform مدیریت شود و منطق ارسال از UI جدا بماند تا تغییر رفتار ورودی بدون تغییر معماری اصلی Composer امکان‌پذیر باشد.
