# راهنمای ساخت و استفاده از Android GPU Inference Engine

## ۱. این پروژه چه کاری انجام می‌دهد؟

این مخزن فقط موتور GPU و برنامه آزمایشی آن را نگه می‌دارد. برنامه آزمایشی یک فایل GGUF را از حافظه گوشی انتخاب می‌کند، آن را در فضای خصوصی برنامه کپی می‌کند و درخواست فعال‌سازی را مستقیماً به موتور GPU می‌فرستد. سپس گزارش تشخیصی کامل را نمایش می‌دهد تا بتوان آن را کپی و برای بررسی ارسال کرد.

این برنامه چت‌بات نیست و تولید متن، صدا، شبکه، حساب کاربری یا مسیر CPU ندارد.

## ۲. پیش‌نیازهای توسعه

- JDK 17
- Gradle 8.13
- Android SDK Platform 36
- Android NDK نسخه 27.2.12479018
- Python 3
- Go 1.24 برای ابزارهای تولید کد Dawn
- دستگاه Android با ABI برابر arm64-v8a برای تست واقعی

در حال حاضر فقط ABI برابر `arm64-v8a` در تنظیمات Android فعال است.

## ۳. ساخت APK

از ریشه مخزن اجرا کنید:

```bash
gradle :test-app:assembleDebug
```

فایل APK:

```
test-app/build/outputs/apk/debug/test-app-debug.apk
```

این APK از ماژول `:engine` استفاده می‌کند؛ کد موتور هنگام build با Android NDK ساخته و در کتابخانه native قرار می‌گیرد.

## ۴. تست روی گوشی

1. APK آزمایشی را روی دستگاه arm64-v8a نصب کنید.
2. برنامه **GPU Engine Test** را باز کنید.
3. دکمه **Import GGUF model and activate GPU engine** را بزنید.
4. فایل مدل با پسوند GGUF را از حافظه انتخاب کنید.
5. برنامه فایل را در فضای خصوصی خودش کپی می‌کند و چهار بایت ابتدایی فایل را برای امضای `GGUF` بررسی می‌کند.
6. موتور با context پیش‌فرض 2048 و بودجه محافظه‌کارانه حافظه GPU فعال‌سازی را امتحان می‌کند.
7. نتیجه و گزارش native در کادر لاگ نمایش داده می‌شود.
8. برای ارسال گزارش، **Copy full log** را بزنید.

مدل از اینترنت دانلود نمی‌شود. فایل انتخاب‌شده باید از قبل روی گوشی موجود باشد و فضای آزاد کافی برای کپی آن وجود داشته باشد.

## ۵. تفسیر نتیجه

- `GPU_ENGINE_LOAD_RESULT=0`: تابع بارگذاری موتور موفق برگشته است. برای نتیجه‌گیری درباره تولید واقعی متن، تست end-to-end جداگانه لازم است.
- کد غیرصفر: بارگذاری یا preflight ناموفق بوده است. مقدار `error` و فهرست blockerها در `GPU_ENGINE_DIAGNOSTICS` علت را مشخص می‌کنند.
- `Unsupported` یا blockerهای tokenizer/architecture/quantization: یعنی ترکیب مدل هنوز توسط موتور تأیید نشده و نباید به زور اجرا شود.
- شناسایی GPU یا عبور self-test به‌تنهایی به معنی پشتیبانی کامل مدل نیست.

گزارش باید همراه مدل/نسخه دقیق فایل، دستگاه، نسخه Android و backend انتخاب‌شده بررسی شود. از عبارت «پشتیبانی همه GPUها و مدل‌ها» استفاده نکنید مگر برای همان ترکیب آزمون معتبر انجام شده باشد.

## ۶. Backend و محدودیت‌ها

- backendهای فعلی: Dawn/WebGPU و Universal OpenGL ES.
- Vulkan عمداً خاموش است.
- OpenCL و مسیر GGML/llama.cpp در این شاخه وجود ندارند.
- backend انتخاب‌شده باید در زمان اجرا روی دستگاه کشف و self-test شود.
- kernelهای هر quantization تنها پس از اعتبارسنجی عددی backend مجاز به اجرا می‌شوند.
- Tokenizerهای ثبت‌شده تا وقتی parity کامل با مرجع و profile دقیق تأیید نشده‌اند، معتبر فرض نمی‌شوند؛ موتور در این وضعیت fail-closed است.
- این پروژه در حال توسعه است؛ موفقیت CI فقط صحت build و تست‌های قراردادی را نشان می‌دهد و جای تست روی GPU واقعی را نمی‌گیرد.

## ۷. اجرای تست‌های مستقل

```bash
bash scripts/test_gpu_engine_contracts.sh
bash scripts/verify_gpu_engine_independence.sh
```

تست قراردادها با کامپایلر C++ میزبان اجرا می‌شود و به Android، Dawn، llama.cpp یا GGML وابسته نیست. تست APK در CI مسیر واقعی Android NDK و لینک native را بررسی می‌کند.

## ۸. CI

با هر push یا pull request:

1. تست‌های مستقل C++ اجرا می‌شوند.
2. مرز استقلال موتور و غیرفعال بودن Vulkan بررسی می‌شود.
3. APK آزمایشی با NDK و ABI برابر arm64-v8a ساخته می‌شود.
4. APK به‌عنوان artifact اجرای GitHub Actions بارگذاری می‌شود.

CI فعلاً نمی‌تواند به‌جای دستگاه فیزیکی، سازگاری درایور GPU یا صحت عددی تمام kernelها را اثبات کند.
