# مشخصات رابط کاربری

**وضعیت:** 🔒 UI v1 — تصمیم‌های طراحی ثبت و یکپارچه شده‌اند
**نسخه هدف:** ۱.۰.۰
**دامنه:** قرارداد و مستندسازی UI/UX؛ بدون پیاده‌سازی

> 🔴 **قانون اجباری: کل UI برنامه باید فارسی و راست‌چین (RTL) باشد.** این الزام برای تمام صفحه‌ها، Header، Sidebar، Menuها، Buttonها، Dialogها، وضعیت‌ها، خطاها، Empty Stateها و تمام متن‌های قابل مشاهده اعمال می‌شود. داده‌های ذاتاً فنی مانند نام مدل، کد، URL و شناسه فنی می‌توانند LTR باشند، اما ساختار و متن پیرامون آن‌ها فارسی و RTL باقی می‌ماند.

## مرجع واحد

**درخت Canonical رابط کاربری در [`ui/UI_TREE.md`](ui/UI_TREE.md) قرار دارد.** این فایل فقط Index و Specification Map است؛ درخت دیگری نباید با آن تعارض داشته باشد.

```text
docs/ui/
├── UI_TREE.md          ← مرجع Canonical ساختار UI
├── README.md           ← نقطه ورود و خلاصه UI
├── DESIGN_SYSTEM.md    ← زبان بصری و Accessibility
├── NAVIGATION.md       ← Header، Sidebar و Navigation
├── STATES.md           ← وضعیت‌های Runtime، Chat و Interaction
├── SCREENS.md          ← جزئیات صفحه‌ها
├── CONTROLS.md         ← کنترل‌های واقعی استخراج‌شده از Core
└── questions/          ← تصمیم‌های مستقل UI
```

## خلاصه Contract

### ساختار اصلی

```text
UI
├── App Shell
│   ├── Header
│   └── Sidebar
├── گفت‌وگو
├── فضای کار
├── عیب‌یابی
├── تنظیمات
└── درباره برنامه
```

جزئیات ساختاری فقط در `ui/UI_TREE.md` مرجع است.

### Header

```text
[ گفت‌وگو │ کار │ ⋯ ]    ● آماده
                          مدل محلی       [ ☰ ]
```

- گروه چپ کمتر از نصف عرض Header است.
- Runtime/AI دوخطی است و ارتفاع آن با دکمه‌های Header برابر است.
- `⋯` شامل «لاگ» و «تنظیمات» است.
- `☰` دکمه گرد Sidebar در سمت راست است.
- کنترل دائمی دیگری در Header وجود ندارد.

### Sidebar

Sidebar از سمت راست باز می‌شود و Overlay نیمه‌شفاف روی محتوای اصلی دارد. ساختار و رفتار کامل آن در `ui/UI_TREE.md` و `ui/NAVIGATION.md` ثبت شده است.

### Chat و Composer

- پیام کاربر: حباب نیمه‌شفاف با رنگ روشن و آرام، با جهت بصری آبی روشن.
- پاسخ مدل: بدون حباب سنگین.
- Composer: Floating و Responsive.
- موبایل: Enter خط جدید؛ ارسال فقط با دکمه.
- دسکتاپ: Enter خط جدید؛ Shift + Enter ارسال.
- هنگام تولید، دکمه ارسال طبق Q21 به «توقف» تبدیل می‌شود.

### Runtime

```text
● آماده
مدل محلی
```

وضعیت‌های کاربرمحور: آماده، در حال کار، در حال تولید، خارج از دسترس، خطا. هر وضعیت رنگ مخصوص خود را دارد، اما رنگ تنها نشانه معنا نیست.

### Workspace

Workspace یک فضای کار **Timeline محور** است و Timeline مرکز بصری آن است.

```text
فضای کار
├── خلاصه اجرای جاری
│   ├── وضعیت
│   ├── مرحله فعلی
│   └── زمان سپری‌شده در صورت وجود واقعی
├── Timeline مرکزی
│   └── Event / Action
│       ├── نام + وضعیت + نتیجه/عنوان خطا
│       ├── Metricهای پردازشی کوچک و کم‌رنگ
│       ├── کنترل‌های مجاز همان لحظه
│       └── ▼ Expand لایه‌ای
│           ├── ▼ اطلاعات درخواست
│           ├── ▼ پردازش و Trace
│           ├── ▼ Preview / Result
│           ├── ▼ Verification / Evidence
│           ├── ▼ Recovery
│           └── مشاهده جزئیات → عیب‌یابی همان Execution
└── تاریخچه عملکرد
    ├── فیلتر
    ├── مقایسه
    ├── خروجی گزارش
    └── جزئیات Expand‌شونده هر اجرا
```

**پنل Contextual مستقل وجود ندارد.** Contextual Detail داخل Expand لایه‌ای همان Event قرار دارد. Progress Bar درصدی وجود ندارد.

### عیب‌یابی

```text
عیب‌یابی
├── خطاها
├── گزارش Execution
│   ├── Trace
│   ├── Error
│   ├── Verification
│   └── Recovery
├── عملکرد
└── گزارش کار حساس
```

«مشاهده جزئیات» از Workspace باید Context همان Execution را حفظ کند و مستقیم روی گزارش متناظر در عیب‌یابی باز شود. تأیید/رد درخواست‌های قابل تأیید از Workspace انجام می‌شود؛ کارت‌های کار حساس از تأییدهای معمولی متمایز هستند و گزارش فارسی قابل مشاهده دارند.

### تنظیمات

تنظیمات از Central Settings Core مدیریت می‌شوند. کنترل‌های Inference طبق Q26 در تنظیمات قرار می‌گیرند. Performance طبق Q40 دارای Visibility در دو سطح دسته و Metric است.

### درباره برنامه

اطلاعات نسخه و مشخصات برنامه در این بخش قرار می‌گیرند.

## اصول غیرقابل نقض

۱. تمام متن‌های UI فارسی و RTL هستند مگر داده ذاتاً فنی.
۲. هیچ Mock یا Placeholder جای وضعیت واقعی را نمی‌گیرد.
۳. UI نباید منطق اجرای Action را در خود پیاده کند.
۴. کنترل‌ها باید بر اساس قابلیت و وضعیت واقعی Core تطبیقی باشند.
۵. اطلاعات فنی و Metricها فقط از داده واقعی می‌آیند.
۶. جزئیات Contextual در Workspace داخل Expand همان Event قرار دارد.
۷. Progress Bar درصدی در Workspace وجود ندارد.
۸. تغییر ساختار اصلی UI ابتدا باید در `ui/UI_TREE.md` ثبت و سپس در اسناد تخصصی منعکس شود.
